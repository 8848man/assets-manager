# Assets Manager 기획서 — 멀티모달 레퍼런스 지식 그래프

Nov 1, 2026 · @RW

## 개요

Assets Manager는 AI가 참고할 레퍼런스를 모아두는 로컬 라이브러리입니다. 화면 왼쪽에는 지식 그래프가 늘 떠 있고, 오른쪽 채팅창에 파일을 넣으면 분석·분류·연결까지 한 번에 처리됩니다.

**문제:** SKILL.md처럼 글로만 관리하면 레퍼런스를 다 담을 수 없습니다. "파스텔 톤, 둥근 막대그래프" 같은 설명으로는 원본 이미지가 주는 정보의 일부만 전해지고, HTML·PDF 스타일은 결과를 보지 않으면 비교하기 어렵습니다. 스킬이 늘어날수록 어떤 스킬을 함께 쓰는지도 기억하기 어려워집니다.

**해결 방향:** 원본 파일(png, html, pdf, md)은 그대로 보관합니다. AI가 바로 쓸 수 있는 텍스트 요약과 토큰을 옆에 붙이고, 레퍼런스끼리의 관계를 그래프로 관리합니다. 사람은 그래프로 보고, AI는 index와 메타데이터를 읽고, 필요하면 원본 이미지를 직접 봅니다.

## 목표와 비목표

**목표**

- 시각 레퍼런스(png·jpg·pdf 페이지)를 원본 그대로 관리하고, AI가 쓸 텍스트 규칙을 함께 만들어 둔다.
- 채팅창에 파일을 끌어다 놓으면 파일 하나가 폴더 저장, 메타데이터, 그래프 연결까지 한 번에 끝난다.
- 레퍼런스 사이의 관계를 종류별로 기록한다(함께 쓰임, 변형, 대체 등).
- 자주 쓰는 조합을 스킬 세트로 묶어 다른 AI 도구로 내보낼 수 있게 한다.
- 모든 데이터는 `assets` 폴더의 파일로 남겨, 앱 없이도 사람과 AI가 읽을 수 있게 한다.

**비목표 (초기 버전)**

- 여러 사람이 동시에 편집하는 협업 기능과 클라우드 동기화
- 이미지 편집이나 디자인 툴 기능
- 레퍼런스를 바탕으로 결과물을 만드는 생성 기능(이 앱은 레퍼런스를 공급하는 역할)

## 관리 대상 에셋 타입

에셋은 6가지 타입으로 나눕니다. 타입마다 원본은 그대로 두고, AI용 텍스트와 미리보기를 따로 만듭니다.

| 타입 | 원본 예시 | AI용으로 만드는 것 | 미리보기 |
| --- | --- | --- | --- |
| 이미지 스타일 | png, jpg (그래프 스타일, 삽화 톤) | 시각 묘사, 색상 팔레트(hex), 구도·질감 규칙 | 썸네일 |
| HTML/CSS 스타일 | html, css, URL 캐프처 | DESIGN.md (YAML 토큰 + 사용 규칙) | 렌더링 스크린샷 |
| PDF/보고서 스타일 | pdf, docx | 페이지 구성, 타이포그래피, 표·차트 규칙 | 대표 페이지 이미지 |
| 글 스타일 | txt, md (블로그 문단, 보고서 문체) | 문체 규칙(어투, 문단 길이, 구성) + 예시 문단 | 본문 발췌 |
| 스킬 | SKILL.md 폴더 | 이름, 설명, 쓰는 에셋 목록 | 설명 카드 |
| 스킬 세트 | 여러 스킬·에셋의 묶음 | 목적, 구성 요소, 사용 순서 | 묶인 노드들의 그룹 |

스킬 세트는 파일을 옮기지 않고 다른 에셋을 참조만 하는 노드입니다. 예를 들어 "네이버 블로그 포스팅 세트"는 글 스타일, 그래프 스타일, 이미지 스타일, 블로그 작성 스킬을 묶습니다.

## 화면 구성

화면은 두 영역으로 나뉩니다. 왼쪽 약 60%에는 지식 그래프가 늘 떠 있고, 오른쪽 약 40%에는 채팅창이 있습니다. 노드를 클릭하면 상세 패널이 그래프 위에 열리고, 채팅과 그래프는 서로 연동됩니다.

&#91;embedded content: 메인 화면 와이어프레임 · 그래프 / 채팅 / 상세 패널\]

채팅의 제안 카드는 그래프에 점선 노드로 바로 미리 보이고, 승인하면 실선으로 바뀝니다.

- **그래프:** 이미지 에셋은 노드에 썸네일로 표시합니다. 스킬 세트는 묶음(헐)으로, 태그는 작은 칩 노드로 보여줍니다. 타입·태그로 필터링하고, 관계 종류에 따라 선 모양을 다르게 합니다.
- **채팅:** 파일을 드롭해 추가하고, 자연어로 검색·수정·연결·세트 만들기를 합니다. 답에 나온 노드는 그래프에서 강조됩니다.
- **상세 패널:** 원본 미리보기, AI용 요약과 spec, 관계 목록을 보여줍니다. "채팅에 첨부"를 누르면 그 노드를 맥락으로 대화를 이어갈 수 있습니다.

## 핵심 사용자 흐름

**흐름 A. 파일 추가 (가장 중요)** — AI가 제안하고 사용자가 승인하는 방식입니다. 승인 전에는 폴더에 아무것도 쓰지 않습니다.

1. 채팅창에 파일을 끌어다 놓고, 필요하면 "네이버 블로그용 그래프 스타일이야" 같은 한마디를 덧붙인다.
2. 앱이 파일 형식을 보고 타입별 파이프라인을 돌린다(여기서 미리보기와 AI용 텍스트가 만들어진다).
3. AI가 제안 카드를 보여준다: 타입, 저장할 폴더, 이름, 태그, 설명, 연결할 기존 노드와 관계 종류.
4. 그래프에 새 노드와 엣지가 점선(미리보기)으로 나타난다.
5. 사용자가 카드에서 수정하거나 채팅으로 "태그에 파스텔 추가해줘"라고 고친 뒤 승인한다.
6. 앱이 원본과 `.meta.yaml`을 폴더에 저장하고, 해당 폴더 index와 `graph.json`을 다시 만든다. 점선이 실선으로 바뀜다.

**흐름 B. 찾기와 묻기** — "보고서에 쓸 차분한 차트 스타일 있어?"처럼 물으면 AI가 index와 메타데이터를 검색해 답합니다. 답에 나온 노드는 그래프에서 강조 표시되고, 노드를 클릭하면 채팅에 그 노드가 맥락으로 들어갑니다.

**흐름 C. 스킬 세트 만들기** — 그래프에서 여러 노드를 선택하거나 채팅으로 "블로그 포스팅에 쓰는 것들 묶어줘"라고 하면 세트 노드가 생깁니다. 세트는 한 번에 내보낼 수 있습니다(외부 AI 사용 방식 참고).

**흐름 D. 정리와 점검** — AI가 주기적으로 두 가지를 찾아 제안합니다. 하나는 연결이 없는 고립 노드, 다른 하나는 거의 같은 중복 에셋입니다. 그래프에 없는 파일을 폴더에 직접 넣은 경우도 감지해 등록을 제안합니다.

## 데이터 모델

기준 데이터는 각 에셋 옆의 `.meta.yaml`입니다. index와 그래프는 모두 이 파일들에서 자동으로 만들어지므로, 직접 고치지 않습니다.

**폴더 구조** (폴더는 타입 기준, 채널·용도는 태그로 표현)

```
assets/
├─ index.md              ← 자동 생성: AI 진입점 (폴더별 요약 + 링크)
├─ graph.json            ← 자동 생성: 노드/엣지
├─ image/                ← 이미지 스타일
│  ├─ index.md
│  ├─ naver-graph-style.png
│  └─ naver-graph-style.meta.yaml
├─ web/                  ← HTML/CSS (DESIGN.md 포함)
├─ document/             ← PDF/보고서
├─ writing/              ← 글 스타일
├─ skills/               ← 스킬 (SKILL.md 폴더들)
├─ sets/                 ← 스킬 세트 (참조만 담은 yaml)
└─ .assets/              ← 썸네일, 임베딩 캐시 (재생성 가능)
```

**메타데이터 스키마** (모든 타입 공통 + 타입별 `spec`)

```yaml
id: naver-graph-style          # 전체에서 유일, 파일명과 동일
type: image-style              # image-style | web-style | doc-style | writing-style | skill | skill-set
title: 네이버 블로그 그래프 스타일
file: naver-graph-style.png
summary: 파스텔 톤 막대그래프, 둥근 모서리, 범례 하단
tags: [chart, pastel, blog, naver]
spec:                          # 타입별로 다름 (변환 파이프라인 결과)
  palette: ['#A8D8EA', '#FFCFDF', '#FEFDCA']
  rules:
    - 막대 모서리 둥글게, 격자선 없음
relations:
  - { type: pairs_with, target: naver-paragraph-style }
  - { type: similar_to, target: report-chart-style, note: 채도만 더 낮음 }
source: 사용자 제작       # 출처/URL
created: 2026-11-01
```

**관계 타입** (엣지)

| 관계 | 뜻 | 예시 |
| --- | --- | --- |
| `pairs_with` | 함께 쓰면 좋음 | 블로그 문단 스타일 ↔ 블로그 그래프 스타일 |
| `similar_to` | 비슷한 대안 | 블로그 차트 ↔ 보고서 차트 |
| `variant_of` | 같은 스타일의 변형 | 다크 모드 버전 → 원본 |
| `derived_from` | 여기서 추출됨 | DESIGN.md → 원본 HTML |
| `uses` | 스킬이 에셋을 참조 | 블로그 작성 스킬 → 문단 스타일 |
| `contains` | 세트의 구성 요소 | 블로그 세트 → 스킬·스타일들 |
| `supersedes` | 이것으로 대체됨 | 새 보고서 스타일 → 예전 것 |

명시한 관계 외에 태그도 노드로 두어, 같은 태그를 가진 에셋끼리는 연한 선으로 자동 연결합니다. 하나의 파일을 여러 에셋으로 쓸 수도 있습니다(예: 한 PDF에서 표 스타일과 표지 스타일을 따로 추출).

**index 자동 생성** — 저장·수정·삭제가 일어날 때마다 다시 만듭니다. 루트 `index.md`에는 폴더별 한 줄 요약만 두고, 폴더 `index.md`에는 에셋마다 제목, 요약, 태그, 관계를 한 줄씩 넣습니다. AI는 루트 index를 먼저 읽고 필요한 폴더로 내려갑니다.

## 타입별 AI 변환 파이프라인

변환은 추가할 때 한 번만 하고 결과를 `spec`에 저장합니다. 이렇게 하면 AI가 쓸 때마다 이미지를 다시 분석하지 않아도 됩니다. 코드로 정확히 뽑을 수 있는 것은 코드로 처리하고, 해석이 필요한 부분만 LLM에 맡깁니다.

| 타입 | 코드로 처리 (결정적) | LLM으로 처리 (해석) |
| --- | --- | --- |
| 이미지 | 썸네일, 주요 색상 k-means 추출, 크기·비율 | 시각 묘사, 스타일 규칙, 태그·관계 제안 (비전 모델) |
| HTML/CSS | 헤드리스 브라우저로 렌더링·스크린샷, 실제 적용된 CSS 값(색·폰트·간격) 수집 | 값을 토큰으로 묶고 사용 의도를 적어 DESIGN.md 작성 |
| PDF/보고서 | 페이지별 이미지 렌더링, 폰트·크기 목록 추출, 페이지 크기·여백 | 표지·본문·표·차트 규칙 정리, 대표 페이지 선택 |
| 글 | 문단 수, 평균 문장 길이, 이모지·소제목 빈도 | 어투·구성 규칙, 예시 문단 발췌, 하지 말아야 할 것 |
| 스킬 | SKILL.md 프런트매터 파싱, 참조 파일 목록 | 다른 에셋과의 `uses` 관계 제안 |
| 스킬 세트 | 구성 요소 존재 여부 검사 | 목적과 사용 순서 설명 |

모든 타입에서 마지막에 텍스트 임베딩을 만들어 `.assets/`에 캐시합니다. 이 임베딩은 비슷한 에셋 찾기, 관계 제안, 중복 감지에 씁니다.

## 외부 AI가 사용하는 방식

이 앱의 가치는 다른 AI 도구가 레퍼런스를 얼마나 쉽게 가져가는지에 달려 있습니다. 그래서 세 가지 방식을 차례로 지원합니다.

1. **폴더 그대로 읽기 (추가 작업 없음)** — Claude Code나 Cursor 같은 도구에 `assets` 폴더를 열고 "루트 index.md부터 읽어"라고 지시합니다.
2. **내보내기** — 에셋이나 스킬 세트를 골라 한 번에 내보냅니다.
   - **Claude 스킬**: SKILL.md에 규칙을 쓰고, 이미지와 DESIGN.md를 참조 파일로 넣은 zip
   - **DESIGN.md 단독 파일**: 웹 스타일을 다른 코딩 에이전트에 줄 때
   - **컨텍스트 번들**: 복사해서 채팅에 붙여넣을 수 있는 마크다운 한 장과 이미지 묶음
3. **MCP 서버 (2단계)** — 외부 AI가 직접 검색하고 가져가게 합니다. 도구는 4개입니다.
   - `search_assets(query, type?, tags?)`
   - `get_asset(id)` — 메타데이터와 spec, 필요하면 원본 이미지
   - `get_related(id, relation?)`
   - `get_skill_set(id)`

## 기술 스택 제안

로컬 웹앱 하나로 시작합니다. 백엔드가 `assets` 폴더를 직접 읽고 쓰며, 브라우저에서 `localhost`로 열어 씁니다. 나중에 필요하면 Tauri로 감싸 데스크톱 앱으로 만듭니다.

| 영역 | 제안 | 이유 |
| --- | --- | --- |
| 백엔드 | Python + FastAPI | 이미지(Pillow), PDF(PyMuPDF), 색상 추출(scikit-learn) 라이브러리가 풍부함 |
| 프런트엔드 | React + Vite | 채팅 UI와 패널 구성이 편함 |
| 그래프 렌더링 | Cytoscape.js (또는 Sigma.js) | 노드에 썸네일 표시, 그룹(스킬 세트) 묶기, 필터링을 지원함. 수천 개 이상이면 Sigma.js |
| HTML 렌더링 | Playwright | HTML 스크린샷과 적용된 CSS 값 추출 |
| LLM | Claude API (비전 지원) | 이미지 분석, 규칙 작성, 채팅에서의 도구 호출 |
| 검색 | SQLite + FTS5, 임베딩은 sqlite-vec | 파일에서 언제든 다시 만들 수 있는 캐시로만 씁 |
| 파일 감시 | watchdog | 폴더에 직접 넣은 파일을 감지해 등록 제안 |

채팅은 LLM에 도구를 주는 방식으로 만듭니다(`add_asset`, `update_meta`, `link`, `search`, `create_set`, `highlight_nodes`). 이 도구들을 나중에 MCP 서버에서도 그대로 재사용합니다.

## MVP 범위와 로드맵

MVP의 기준은 "파일 하나를 끌어다 놓으면 그래프에 연결된 노드로 나타나고, Claude Code가 index를 읽고 그 스타일대로 작업한다"입니다. 지금 있는 네이버 블로그 파일 3개로 먼저 검증합니다.

1. **0단계 — 스키마와 스크립트 (앱 없이)**
   - `.meta.yaml` 스키마를 확정하고, 기존 파일 3개에 메타데이터를 붙인다.
   - `build_index.py`로 index.md와 graph.json을 만든다.
   - 정적 HTML 그래프 뷰어를 만든다.
2. **1단계 — MVP 앱**
   - 왼쪽 그래프와 오른쪽 채팅 화면을 만든다.
   - 이미지와 글 타입을 추가하는 흐름(제안 → 승인)을 넣는다.
   - 노드를 클릭하면 상세 패널이 열리고, 채팅으로 찾을 수 있게 한다.
3. **2단계 — 타입 확장**
   - HTML/CSS(DESIGN.md 자동 생성), PDF, 스킬 타입을 추가한다.
   - 스킬 세트를 만들고 Claude 스킬 zip으로 내보낼 수 있게 한다.
4. **3단계 — 외부 연동과 점검**
   - MCP 서버를 연다.
   - 임베딩으로 비슷한 에셋·중복·고립 노드를 점검한다.
   - 폴더 감시를 추가한다.

## 열린 질문

- [ ] 폴더 기준을 타입(이미지/웹/글)으로 할지, 채널(블로그/보고서)로 할지? 이 기획은 타입 기준을 전제로 합니다.
- [ ] 기존 `blog_post`, `http_style`, `report` 폴더를 새 구조로 옮길지? (`http_style`은 `html_style` 의도인지도 확인 필요)
- [ ] Obsidian에서도 열리게 할지? 열리게 하려면 메타데이터를 별도 yaml 대신 md 프런트매터로 두어야 합니다.
- [ ] LLM은 Claude API 하나로 고정할지, 로컬 모델 옵션도 둘지? (API 비용과 프라이버시를 함께 봐야 함)
- [ ] 보안이 필요한 레퍼런스(회사 자료 등)를 외부 API로 보내도 되는지?
- [ ] 외부 사이트에서 가져온 레퍼런스의 출처와 저작권 표시를 어떻게 할지?
