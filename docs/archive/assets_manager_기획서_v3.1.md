# Assets Manager 기획서 v3.1 — 상속형 레퍼런스 그래프, 드롭 엔진, AI 작성 흐름

Nov 4, 2026 · @RW · v2에 1단계 테스트 결과와 2단계 그릴링(Q31~Q47)을 반영한 v3, 여기에 노드 위치 저장과 폴더 요청(Q49~Q55)을 더한 판

## 1. 한 문장 요약

내 표준(규칙과 레퍼런스)을 **상속 그래프**로 관리하고, 노드를 **끌어서 외부 AI 앱에 떨어뜨리면** 항상 같은 프롬프트와 첨부 파일이 넘어간다. 새 레퍼런스는 **작업하던 AI가 규격대로 노드 파일을 써 주고**, 앱은 결정적인 값 추출, 검사, 기록, 되돌리기를 맡는다.

## 3. 1단계 테스트에서 배운 것 (Q31)

- 드롭은 세 앱 모두 동작했다. 어긋난 것은 **결과의 일관성**이었다.
- 같은 삽화 지시에 GPT는 **캐릭터의 개성**에, Claude는 **배치와 형상**에 집중했다. 지시가 비어 있는 부분을 모델이 자기 성향대로 채운 것이다.
- 내 표준에 더 가까운 것은 GPT 쪽이었다. 점 눈은 유지하되 **표정이 있는** 캐릭터.
- 보정할 수 있는 것: 무엇을 중요하게 볼지. 보정할 수 없는 것: 엔진 차이(Claude는 이미지를 직접 그리지 않음). 목표는 "같은 그림"이 아니라 **"같은 점을 중요하게 보는 것"**이다.

## 4. 핵심 개념

### 4.1 노드 종류

| 종류 | 무엇 | 파일 형식 |
| --- | --- | --- |
| 레퍼런스 노드 | 원본 파일 하나 | 원본 옆 사이드카 `*.meta.yaml` |
| 규칙 노드 | 키-값 규칙 묶음, 다른 규칙 노드를 상속 | md 노트(프런트매터 = 규칙) |
| **미등록 노드** (신규) | 레퍼런스 폴더에 있지만 `.meta.yaml`이 없는 파일 | 원본만 있음. 그래프에 점선으로 표시, "AI로 등록하기" 제공 |
| **AI 노드** (신규) | 드롭 대상 AI (`targets.yaml`) | 파일 없음, 그래프에 자동 생성 |

### 4.2 규칙, 상속, 기본값 (v2와 같음)

- 키-값 규칙, 값은 텍스트 또는 `ref:<id>`. 덮어쓰기 단위는 키.
- 자유 다중 상속, `inherits` 뒤쪽이 이김, 순환 금지. 상속 선언이 없으면 `_defaults` 상속.
- `_defaults/`는 레이어 0. 기본값에서 온 값은 눈에 띄게 표시.
- 지시문은 키 템플릿이 기본, 엣지 `note:`가 대체. "고급"에 숨김.
- 조립 엣지(`inherits`, 키 엣지)만 프롬프트에 들어가고, 정보 엣지는 들어가지 않음.

### 4.3 측면별 키와 자가 점검 (Q44)

- 이미지 관련 키를 측면별로 나눈다.
  - `character_style` (필수): 캐릭터의 얼굴, 표정, 개성, 비례
  - `composition` (권장): 배치, 형상, 흐름
  - `image_style` (권장): 선, 채색, 질감 같은 화풍
- 키 정의에 `check:`(점검 문장)를 둔다. 레퍼런스 노드도 자기만의 `check:` 목록을 가질 수 있다.
- 조립할 때 앱이 점검 문장을 모아 프롬프트 끝에 **"출력 전 자가 점검"** 체크리스트로 붙인다. 같은 목록이 결과 판정(골든 샘플 비교)의 채점표가 된다.

### 4.4 우선순위 (Q46~Q47)

- 겹치는 키 쌍의 우선순위를 키 어휘에 기본값으로 둔다.
  - `character_style` > `image_style` (범위: 캐릭터)
  - `palette` > `chart_style`, `image_style` (범위: 색)
- 세트는 `precedence:`로 순서를 뒤집을 수 있고, 상속된다.
- 두 키가 함께 있으면 앱이 **첨부 순서**(우선하는 쪽 먼저)와 **우선순위 문장**("캐릭터에 관해서는 [1]을 [2]보다 우선합니다")을 자동으로 붙인다.
- 캐릭터 레퍼런스는 선택이다. 없으면 이미지 레퍼런스가 캐릭터까지 맡는다. 캐릭터는 세트마다 다를 수 있으므로 키 어휘에는 범용 규칙만, 구체적인 캐릭터는 세트나 캐릭터 레퍼런스 노드에 둔다.

## 5. 드롭 엔진 (v2 + 보정)

- 조립은 결정적이고 저장하지 않는다. 하이브리드 패키지(파일 + 프롬프트 + 경로), 패키지 동등성(세 앱이 보는 본문은 같음).
- 한도 경고와 "자동 덜어내기"(spec 대체 → 컨택트 시트 → 키 제외), 민감도 경고.
- **프롬프트 구성 순서:** 규칙 → 우선순위 문장 → 첨부 목록 → 출력 전 자가 점검 → (Codex) 파일 경로.

## 6. AI 작성 흐름 (2단계, Q36~Q42)

### 6.1 역할 분담

| 누가 | 무엇을 |
| --- | --- |
| `extract.py` (코드) | 결정적인 값: 이미지 크기·주요 색 hex, 글 통계(문단·문장 길이·소제목·이모지·존댓말 비율), HTML/CSS 값(색·폰트·여백·모서리·애니메이션 시간), PDF(페이지·폰트·크기) |
| 작업하던 AI | 해석: spec 문장, 태그, 레퍼런스 고유 점검 목록, 필요하면 세트 규칙 |
| 앱 | 작성 프롬프트 생성, 결과 받기, 검사, 기록, 되돌리기 |

`extract.py`는 HTML을 브라우저 없이 텍스트에서 읽는다(얇은 버전). 화면에 실제로 어떻게 보이는지는 AI가 해석한다.

### 6.2 흐름

1. **파일 넣기:** 앱 창에 파일을 끌어다 놓거나, 레퍼런스 폴더(`image/`, `web/`, `document/`, `writing/`)에 직접 넣는다. 메타 파일이 없으면 **미등록 노드**(점선)가 된다.
2. **AI로 등록하기:** 미등록 노드에서 대상 AI를 고르고 손잡이를 끈다(또는 프롬프트 복사). 작성 프롬프트에는 규격, 현재 키 목록, 기존 노드 id, 추출 방법이 들어간다.
   - **에이전트(Codex 등):** "`extract.py`를 실행하고 원본 옆에 `.meta.yaml`을 써라". AI가 폴더에 직접 쓴다.
   - **채팅형(Claude, ChatGPT):** 패키지에 `extract.py`와 원본을 함께 첨부한다. AI가 코드 실행 환경에서 돌리고, 결과를 `assets-import.zip` 하나로 내려받게 준다. 미리 뽑은 값도 프롬프트에 넣어 실행할 수 없을 때를 대비한다.
3. **돌아오기:** 에이전트는 이미 폴더에 썼다. 채팅형은 zip을 앱 창에 끌어다 놓으면 앱이 풀어서 맞는 폴더에 넣는다.
4. **검사:** 앱이 폴더를 다시 읽고 문제(id 중복, 없는 레퍼런스, 모르는 키)를 경고로 보여 준다. **승인 단계는 없다.** 새로 들어온 노드는 "새로 추가됨"으로 표시된다.

### 6.3 작성자 기록 (Q32)

- 노드에 `authored_by: <대상 id>`를 남긴다. 작성 프롬프트가 AI에게 직접 쓰게 하고, 비어 있으면 zip을 가져올 때 앱이 드롭 히스토리에서 채운다.
- 그래프에서 AI 노드 → 레퍼런스 노드로 "작성" 정보 엣지가 그려진다.

## 7. 기록과 되돌리기 (Q34~Q39)

### 7.1 드롭 히스토리

- `history/drops.jsonl`에 한 줄씩 쌓는다: 시각, 노드, 대상, 방식(`drag` 확인됨 / `copy` 확인 안 됨), 종류(`prompt` 드롭 / `author` 작성 요청), 프롬프트 지문, 파일 목록.
- 기록되는 대상은 "사용자가 고른 대상"이다. 앱은 실제로 어느 창에 놓였는지 알 수 없다.
- 그래프의 규칙 노드 → AI 노드 "드롭 N회" 정보 엣지는 이 파일에서 계산한다.
- `history/`는 캐시가 아닌 정식 데이터다(`.assets/`와 분리).

### 7.2 버전 보관, 휴지통, Git

- **버전 보관(항상):** 앱이 폴더를 읽을 때 노드 파일의 내용이 바뀌었으면 새 내용을 `history/versions/`에 보관한다(파일당 최근 20개, 원본은 5MB 이하만). 상세 패널에서 이전 버전으로 되돌린다.
- **휴지통:** 삭제하면 노드 파일들을 `history/trash/<시각>/`로 옮긴다. 휴지통에서 복구한다.
- **Git(있으면):** 라이브러리 폴더가 Git 저장소면 변경이 감지될 때마다 자동으로 커밋한다. 저장소가 없으면 처음 실행할 때 만든다(상위 폴더가 이미 저장소면 만들지 않는다). `.assets/`, `history/versions/`, `history/trash/`는 커밋하지 않는다.
- **변경 감지(Q12)**는 막지 않고 알려 주기만 한다.

## 8. 화면

- 그래프: 규칙(사각형), 레퍼런스(원, 썸네일), **미등록(점선 원)**, **AI(마름모)**. 조립 엣지 실선, 정보 엣지 점선.
- 상세 패널: 레퍼런스 미리보기, 규칙 표, 드롭 영역, **AI로 등록하기**(미등록 노드), **삭제**, **이전 버전**(고급).
- 창 전체가 **가져오기 영역**: 파일이나 zip을 놓으면 라이브러리에 추가.
- 상단: 변경 감지, **휴지통**, 고급 토글.

## 9. 폴더 구조

```
assets/
├─ index.md, graph.json        ← 자동 생성
├─ _defaults/                  ← 레이어 0 (keys.yaml, targets.yaml, defaults.md)
├─ principles/  sets/          ← 규칙 노드
├─ image/ web/ document/ writing/ skills/ golden/   ← 레퍼런스 노드 (+ 미등록 파일)
├─ history/                    ← 정식 데이터
│  ├─ drops.jsonl
│  ├─ versions/                ← 버전 보관 (Git 제외)
│  └─ trash/                   ← 휴지통 (Git 제외)
├─ app/                        ← 앱 코드 (core/extract.py 포함)
└─ .assets/                    ← 캐시
```

## 10. 메타데이터 스키마 추가분

```yaml
# 레퍼런스 노드
```

```yaml
# keys.yaml 키 정의
character_style:
  check: "캐릭터가 레퍼런스의 얼굴 표현 규칙을 지키는가"
  precedence:
    - { over: image_style, scope: 캐릭터 }
```

```yaml

  - { first: image_style, over: character_style, scope: 캐릭터 }
```

## 12. v3.1 추가: 노드 위치 저장과 폴더 → 노드 AI 요청 (Q49~Q55)

### 12.1 노드 위치 저장
- 그래프에서 노드를 옮기면 라이브러리의 `layout.json`(노드 id → 좌표)에 저장한다. 정식 데이터라 Git에 기록된다.
- 위치가 없는 새 노드는 연결된 노드 근처에 자동 배치된다. 상단 "배치 초기화"로 자동 정렬하고 다시 저장할 수 있다.
- id를 바꾸면 그 노드의 위치는 잃는다(감수).

### 12.2 원칙 보정
**사람이 넣은 것은 바로 반영, AI가 만든 구조는 미리 보고 확정한다.** 파일 하나를 넣거나 미등록 파일을 AI로 등록하는 흐름은 v3 그대로 바로 반영된다. 폴더를 노드에 놓아 AI가 노드 여러 개와 연결을 만드는 흐름만 확인 단계를 거친다.

### 12.3 흐름
1. **놓기:** 폴더(또는 파일 여러 개)를 그래프의 노드 위에 놓는다. 노드가 하이라이트되고 안내 문구가 바뀐다. 빈 공간에 폴더를 놓아도 같은 흐름이다(연결 대상 없음).
2. **요청 확인 (Q49-C 앞단):** 앱이 AI 없이 알 수 있는 것만 보여 준다. 놓은 노드, 권장 해석, 새 파일 목록(종류·크기·주요 색), **이미 있는 파일**(지문 일치 → 기존 노드 id), 제외된 파일(지원하지 않는 형식, 50개 초과). AI와 요청 문구를 고르고 "요청 만들기".
3. **보내기:** 손잡이를 끌어 AI에 놓거나 프롬프트를 복사한다. 요청은 `inbox/<요청 id>/`에 보관된다(`request.json`, `src/` 원본 사본).
4. **결과 수신:**
   - 채팅형: AI가 준 `assets-import.zip`(plan.yaml 포함)을 창에 놓는다.
   - 에이전트: AI가 `inbox/<요청 id>/out/`에 쓴다. 상단에 "AI 결과 도착"이 뜬다.
5. **결과 확인 (Q49-C 뒷단):** 오른쪽 패널에 항목별 체크 목록이 뜨고, 그래프에 점선으로 미리 그려진다. "체크한 항목 적용"을 누르면 그때 파일로 쓴다. 미리 본 자리에 노드가 그대로 놓인다.

### 12.4 해석: AI가 판단, 가이드 프롬프트로 규격화 (Q50)
놓은 노드 종류별 **권장 해석**을 프롬프트에 넣는다. AI가 다르게 판단하면 항목의 `reason`에 이유를 쓴다.

| 놓은 노드 | 권장 해석 |
| --- | --- |
| 세트 | 레퍼런스로 등록하고 알맞은 키로 세트에 연결 |
| 원칙·기본값 | 새 세트를 만들어 그 노드를 상속 |
| 레퍼런스 | 변형이나 비슷한 대안으로 등록 (`variant_of`, `similar_to`) |
| 빈 공간 | 연결 없이 레퍼런스로만 등록 |

### 12.5 결과 형식: `plan.yaml` 계획서 (Q51)
AI는 기존 파일을 고치지 않는다. 새 노드 파일과 계획서만 돌려주고, 앱이 계획서를 적용한다.

```yaml
request: req-20261104-062855
summary: 무엇을 만들었는지 한 줄
create:
  - { path: image/card-ui.meta.yaml, reason: ... }
update:                       # 기존 규칙 노드의 키 추가·변경 (삭제 불가)
  - node: naver-blog-post
    set_rules: { css_style: "ref:landing-tokens" }
    reason: ...
relations:
  - { from: dark-hero, type: variant_of, to: card-ui, reason: ... }
```

- 적용할 때 해당 키만 바꾸고 노드의 나머지 규칙은 보존한다. 엣지 `note`가 있던 키는 값만 바꾸고 `note`는 유지한다.
- 새 노드 생성을 빼면 그 노드에 기대는 항목(그 노드를 가리키는 키, 연결)도 함께 빠진다.

### 12.6 덮어쓰기 (Q53)
이미 값이 있는 키를 바꾸는 항목은 **"기존 키 덮어쓰기"**로 따로 묶어 빨간색으로 보여 준다. 전후 값과 **영향받는 노드 목록**(그 세트 + 상속하는 하위 노드)을 함께 표시하고, **기본으로 체크가 꺼져 있다.**

### 12.7 중복 (Q54)
- 요청할 때 앱이 파일 지문을 라이브러리와 대조해, 이미 있는 파일은 프롬프트에 "이미 `<id>`로 등록됨, 새로 만들지 말고 연결만"으로 표시한다.
- 결과를 받으면 다시 대조한다. AI가 지시를 어기고 같은 파일로 새 노드를 만들었으면 "중복 노드" 경고와 함께 체크를 꺼 둔다.

### 12.8 큰 폴더 (Q55)
- 한 번에 최대 50개 파일(하위 폴더 포함). 초과분은 요청 확인에서 알린다.
- 채팅형 AI의 첨부 한도를 넘으면 이미지는 번호 붙은 **컨택트 시트** 한 장, 텍스트(html·css·txt·md)는 **묶음 파일** 하나로 합친다. 색상 hex 같은 값은 앱이 원본에서 미리 뽑아 프롬프트에 넣으므로 해상도 저하의 영향을 받지 않는다.
- 에이전트는 원본 경로를 직접 받으므로 합치지 않는다.

### 12.9 폴더 구조 추가
```
assets/
├─ layout.json            ← 노드 위치 (Git 기록)
└─ inbox/<요청 id>/       ← 폴더 요청 (Git·로더 제외)
   ├─ request.json
   ├─ src/                ← 놓은 파일 사본
   ├─ package/            ← 보낸 프롬프트, 컨택트 시트, 묶음
   └─ out/                ← AI 결과 (plan.yaml + 새 노드 파일)
```
