# Assets Manager 기획서 v2 — 상속형 레퍼런스 그래프와 드롭 엔진

Nov 1, 2026 · @RW · v1(같은 폴더의 `assets_manager_기획서.md`)을 그릴링 인터뷰(Q1~Q29)로 다시 설계한 판

## 1. 한 문장 요약

내 표준(규칙과 레퍼런스)을 **상속 그래프**로 관리하고, 노드를 **끌어서 외부 AI 앱(Codex, Claude 데스크톱, ChatGPT 웹)에 떨어뜨리면** 항상 같은 프롬프트와 첨부 파일이 넘어가서, 어떤 AI에서 작업해도 결과물이 내 표준대로 나오게 하는 데스크톱 앱.

## 2. v1에서 바뀐 점

| 영역 | v1 | v2 | 근거 |

## 3. 사용자와 목표

- **사용자:** 나부터 쓰고, 나중에 AI 초보자에게 배포할 수 있게 만든다(Q18-B).
  - `_defaults/`에는 범용 기본값만, 내 취향은 그 위의 "내 전역 원칙" 노드에 둔다.
  - 경로는 `assets` 루트 기준 상대 경로로 저장하고, 드롭하는 순간에만 절대 경로로 바꾼다.
- **해결할 문제 세 가지(Q5)**
  1. 업무 문서: 공통 원칙(시각화 예시, 설명 난이도, 형식)을 매번 프롬프팅해야 함 → **규칙 노드와 상속**
  2. 웹/디자인: CSS, 애니메이션, 섹션 컨셉을 꺼내 쓸 창고가 없음 → **레퍼런스 노드와 ref 값**
  3. 콘텐츠: 이미지, 글쓰기 표준이 아직 고정되지 않음 → **골든 샘플 승격**(10장)
- **비목표(초기)**: 협업과 클라우드 동기화, 이미지 편집, 결과물 생성(앱은 프롬프트와 레퍼런스를 공급만 함), MCP 서버.

## 4. 핵심 개념

### 4.1 노드는 두 종류

| 종류 | 무엇 | 파일 형식(Q26) | 예 |
| --- | --- | --- | --- |
| **레퍼런스 노드** | 원본 파일 하나 | 원본 옆 사이드카 `*.meta.yaml` | `image/naver-graph-style.png` + `.meta.yaml` |
| **규칙 노드** | 키-값 규칙의 묶음. 다른 규칙 노드를 상속 | md 노트(프런트매터 = 규칙, 본문 = 사람용 설명) | `_defaults/defaults.md`, `principles/global.md`, `sets/naver-blog-post.md` |

v1의 `skill-set` 타입은 "키를 가진 규칙 노드"로 통합된다. SKILL.md는 레퍼런스 타입 중 하나(`skill`)가 된다.

### 4.2 규칙은 키-값, 값은 텍스트 또는 레퍼런스(Q14)

```yaml
rules:
  audience_level: 중학생도 이해하는 수준          # 텍스트 값
  chart_style: ref:naver-graph-style             # 레퍼런스 값
  image_style:
    value: ref:naver-illustration-style
    note: 캐릭터와 선 굵기만 참고하세요.            # 엣지별 지시문 (고급)
```

- 덮어쓰기 단위는 **키**다. 값이 무엇이든 같은 키면 아래쪽(더 구체적인 노드)이 이긴다.
- 키 엣지는 그래프에서 이름 붙은 선이 된다. "이 이미지가 **무슨 역할로** 참여하는가"가 보인다.
- 남은 `ref:` 값들이 곧 드롭할 첨부 파일 목록이다.

### 4.3 키 어휘(Q15)

- 앱이 `_defaults/keys.yaml`에 기본 키 목록을 제공한다. 키마다 라벨, 영역, 중요도(`required`/`recommended`/`optional`), 동의어, 지시문 템플릿을 가진다.
- 사용자 정의 키를 허용한다. 새 키가 기존 키의 동의어(`aliases`)와 일치하면 "같은 뜻으로 보입니다. 합칠까요?"라고 경고한다. (MVP: 동의어 목록 일치 검사. 2단계: LLM 유사도 검사)

### 4.4 상속(Q13)

- 자유 다중 상속. `inherits: [a, b]`에서 **뒤에 오는 부모가 이긴다.** 자기 자신의 규칙이 가장 마지막에 적용된다.
- 상속 선언이 없는 규칙 노드는 자동으로 `_defaults`를 상속한다.
- 순환 상속은 로드할 때 검사하고, 해당 노드를 오류로 표시하고 조립하지 않는다.

### 4.5 기본값(레이어 0, Q16~Q17)

- 앱이 처음 실행될 때 `assets/_defaults/`로 복사한다. 이후로는 폴더 쪽이 기준이다. 앱 없이 폴더만 있어도 같은 결과가 나와야 한다.
- 기본값은 그래프의 최상위 노드로 보인다. 앱 업데이트로 새 기본값이 나오면 diff와 승인을 거친다.
- 조립 결과에서 **기본값에서 온 값은 눈에 띄게 표시**한다. 표준을 정하지 않은 채 기본값으로 가려지는 것을 막기 위해서다.

### 4.6 지시문(Q25)

레퍼런스를 첨부할 때 "이 파일에서 무엇을 보라"는 문장은 **키 템플릿이 기본**이고, 엣지의 `note:`가 있으면 그것이 대체한다. 지시문 편집은 "고급" 안에 둔다.

### 4.7 엣지 종류(Q24)

| 종류 | 엣지 | 그래프 표시 | 프롬프트 |
| --- | --- | --- | --- |
| 조립 엣지 | `inherits`, 키 엣지(`chart_style →` 등) | 실선 | **들어감** |
| 정보 엣지 | `pairs_with`, `similar_to`, `variant_of`, `supersedes`, `derived_from` | 점선 | 절대 안 들어감 |

v1의 `contains`, `uses`는 키 엣지로 흡수한다. 정보 엣지로 "키로 추가할까요?"를 제안하는 기능은 MVP 이후로 미룬다.

## 5. 드롭 엔진

### 5.1 조립(Q11)

1. 드래그한 규칙 노드에서 상속 순서를 계산한다(부모를 순서대로 깊이 우선, 중복 제거, 자기 자신이 마지막).
2. 그 순서대로 규칙을 덮어써서 키마다 최종 값과 **출처 노드**를 기록한다.
3. 값을 문장으로 바꾼다. 텍스트 값은 키 템플릿으로, ref 값은 "첨부 [n] 파일명: 지시문"으로 바꾼다.
4. 결과는 **저장하지 않는다.** 그래프가 같으면 결과는 글자 하나까지 같다.

### 5.2 하이브리드 패키지(Q8~Q10, Q20)

드래그 한 번에 다음이 함께 나간다.

- **파일:** `prompt.md`(조립된 프롬프트) + 레퍼런스 원본 파일들
- **클립보드:** 같은 프롬프트에 절대 경로 목록을 붙인 텍스트(Codex처럼 파일을 직접 읽는 에이전트용)

| 대상 | 주된 전달 방식 | 받는 것 |
| --- | --- | --- |
| Codex | 경로 + 파일 | `prompt.md` + 원본, 또는 클립보드의 경로 포함 텍스트 |
| Claude 데스크톱 | 파일 | `prompt.md` + 원본 |
| ChatGPT 웹 | 파일 | `prompt.md` + 원본 |

**패키지 동등성:** 전달 방식은 달라도 AI가 읽는 프롬프트 본문은 세 앱 모두 같다. 차이는 경로 목록 한 단락뿐이다.

### 5.3 한도와 자동 덜어내기(Q28~Q29)

- 대상 앱마다 한도(첨부 파일 수, 파일 크기, 글자 수)를 `_defaults/targets.yaml`에 둔다. **초깃값은 추정치이므로 실제로 확인해서 고쳐야 한다.**
- 한도를 넘으면 드래그하기 전에 경고하고, **"자동 덜어내기"** 버튼을 제공한다. 순서는 다음과 같다.
  1. 첨부 파일을 저장된 `spec` 텍스트로 바꾼다(선택 → 권장 → 필수 키 순서). `spec`이 없으면 건너뛰고 "텍스트 대체 불가"로 표시한다.
  2. 남은 이미지 여러 장을 번호를 붙인 컨택트 시트 한 장으로 합친다.
  3. 그래도 넘으면 선택 → 권장 키 순서로 규칙을 뺀다. 필수 키는 빼지 않는다.
- 세 단계 모두 AI 호출 없이 결정적으로 동작한다. 결과는 diff 요약 한 장으로 보여 준다.
- 기본은 해당 대상에만 적용한다. "고급"에서 "세 앱 모두 같은 기준으로 덜어내기"를 고를 수 있다.

### 5.4 민감도(Q27)

- 레퍼런스나 규칙 노드에 `sensitivity: internal`을 표시할 수 있다.
- 민감도는 상속되는 속성이 아니라 **조립 결과에서 계산한다.** 패키지에 `internal` 노드가 하나라도 있으면 경고하고, 그래프에서 그 노드와 상속 경로를 빨갛게 표시한다.
- 대상별 정책(`allow_internal`)이 `false`면 "민감 자료를 텍스트로 대체" 버튼을 제공한다. 정책은 "고급"에 둔다.

## 6. 변경 통제(Q12)

- 조립 결과의 스냅숏을 승인할 때마다 `.assets/snapshots/`에 저장한다.
- 파일을 고친 뒤 앱을 열면, 현재 조립 결과가 스냅숏과 다른 규칙 노드를 모두 찾아 **"변경 감지: N개"**로 알리고 노드별 diff를 보여 준다. 사용자가 승인하면 스냅숏을 갱신한다.
- 상위 노드를 선택하면 그 노드를 상속하는 모든 하위 노드(영향 범위)를 그래프에서 하이라이트한다.

## 7. 화면

- **왼쪽(약 60%): 지식 그래프.** 규칙 노드는 둥근 사각형, 레퍼런스 노드는 썸네일 원, 기본값은 회색. 조립 엣지는 실선, 정보 엣지는 점선.
- **오른쪽(약 40%): 상세 패널.** png는 이미지와 설명, html은 iframe 실행기와 설명, 글은 본문 발췌. 규칙 노드는 최종 규칙 표(값과 출처) + 드롭 영역.
- **드롭 영역:** 대상 선택(Codex / Claude / ChatGPT) → 한도와 민감도 상태 → **끌어서 놓는 손잡이** → 자동 덜어내기 버튼.
- **정보 과부하 방지(Q25):** 기본 화면에는 노드, 키 이름, 연결된 레퍼런스, 기본값 표시, 드래그만 보인다. 지시문, 상속 순서, 덮어쓰기 경로, 대상별 패키지 구성은 **"고급"** 토글 안에 둔다.
- 채팅 패널은 2단계에서 추가한다.

## 8. 폴더 구조

폴더는 타입 기준이다. 채널(블로그, 리포트)은 세트 노드가 표현한다.

```
assets/                       ← 라이브러리 루트 (D:\projects\assets)
├─ index.md                   ← 자동 생성: AI 진입점
├─ graph.json                 ← 자동 생성: 노드와 엣지
├─ _defaults/                 ← 레이어 0
│  ├─ defaults.md             ← 범용 기본 규칙
│  ├─ keys.yaml               ← 키 어휘, 중요도, 지시문 템플릿
│  └─ targets.yaml            ← 드롭 대상과 한도
├─ principles/                ← 전역·영역 원칙 (규칙 노드)
├─ sets/                      ← 산출물 세트 (규칙 노드)
├─ image/  web/  document/  writing/  skills/   ← 레퍼런스 노드
├─ golden/                    ← 승격된 골든 샘플 (레퍼런스 노드)
├─ app/                       ← 앱 코드 (라이브러리로 읽지 않음)
└─ .assets/                   ← 캐시: 드롭 패키지, 스냅숏 (지워도 재생성됨)
```

기존 `blog_post/naver_blog`의 파일 3개는 새 구조로 **복사**하고 원본은 그대로 둔다. 빈 `http_style`은 `web/`으로 대체한다.

## 9. 메타데이터 스키마

**레퍼런스 노드** (`image/naver-graph-style.meta.yaml`)

```yaml
id: naver-graph-style
type: image            # image | web | document | writing | skill
title: 네이버 블로그 그래프 스타일
file: naver-graph-style.png
summary: 2x2 포지셔닝 매트릭스, 파스텔 원형 노드
spec: |                # 덜어내기 1단계에서 첨부 대신 쓰는 텍스트
  ...
tags: [chart, pastel, blog]
sensitivity: public    # public | internal
relations:             # 정보 엣지 (프롬프트에 안 들어감)
  - { type: similar_to, target: report-chart-style }
source: 사용자 제작
```

**규칙 노드** (`sets/naver-blog-post.md`)

```markdown
---
id: naver-blog-post
type: rule
kind: set              # defaults | principle | set
title: 네이버 블로그 포스팅
inherits: [global]
rules:
  tone: 친근한 존댓말(~해요체)
  chart_style: ref:naver-graph-style
priorities:            # 키 중요도 덮어쓰기 (고급)
  image_style: required
---
사람이 읽는 설명
```

## 10. 골든 샘플과 성공 기준(Q20~Q22)

- **기준선은 골든 샘플이다.** 세트마다 "이게 내 표준의 완성형"인 결과물 하나를 둔다.
- 골든 샘플은 **AI와 반복해서 만들고 내가 승인해서 승격**한다. 부품 레퍼런스를 드롭 → 결과를 다듬음 → `golden/`에 넣고 세트의 `golden_sample` 키로 연결한다.
- 자기 채점을 막기 위해 세 앱의 결과를 **출처를 가린 채로** 골든 샘플과 비교한다.
- **MVP 성공 기준:** `naver-blog-post` 세트를 세 앱에 각각 드롭해 같은 주제의 글을 쓰게 했을 때,
  1. 세 결과의 양식(구조, 톤, 시각화 방식)이 서로 일치하고,
  2. 블라인드 비교에서 골든 샘플 수준 이상으로 판정된다.

| --- | --- | --- |
| 데스크톱 셸 | **Tauri v2** | 네이티브 파일 드래그는 `tauri-plugin-drag`. 실패 시 Electron으로 전환(탈출구) |
| 코어와 서버 | **Python 사이드카** (표준 라이브러리 HTTP 서버 + PyYAML + Pillow) | MVP는 의존성을 최소화. 2단계 변환 파이프라인도 같은 프로세스에 붙임 |
| UI | 빌드 단계 없는 HTML/JS + Cytoscape.js(로컬 번들) | 브라우저로 열어도 동작(드래그는 텍스트·클립보드로 대체) |
| 2단계 LLM | Claude API(비전) | 변환, 동의어 검사. 민감 노드는 보내지 않음 |

## 12. 로드맵

**0단계 — 드래그 실험 (가장 먼저)**
- Tauri 셸에서 png + md 여러 개를 Codex, Claude 데스크톱, ChatGPT 웹에 동시에 드롭해 모두 첨부되는지 확인한다.

**1단계 — MVP: 드롭 엔진**
- 로더(사이드카 yaml + md 노트 → 단일 모델), 순환 검사, 동의어 경고
- 상속 조립, 출처 추적, 지시문 템플릿과 엣지 `note`
- 대상별 패키지, 한도 경고, 자동 덜어내기(spec 대체 → 컨택트 시트 → 키 제외)
- 민감도 경고와 텍스트 대체
- 변경 감지(스냅숏 diff)와 영향 범위 하이라이트
- 그래프, 상세 패널(이미지·iframe·텍스트), 고급 토글, 드래그 손잡이
- `index.md`, `graph.json` 자동 생성
- 검증 세트: `naver-blog-post` → 골든 샘플 1편 승격

**2단계 — 입력 흐름**
- 채팅으로 파일 추가, 타입별 변환 파이프라인(spec과 키 제안), 제안 → 승인
- LLM 동의어 검사, 정보 엣지 기반 키 추가 제안

**3단계 — 확장**
- HTML/CSS(DESIGN.md), PDF, 스킬 타입 변환. MCP 서버. 배포(설치 파일, API 키 입력, 기본값 업데이트 채널)

## 13. 열린 질문 (2단계 그릴링 대상)

- [ ] 변환 파이프라인이 레퍼런스 하나에서 어떤 키와 `spec`을 제안하는가? 하나의 파일이 여러 키를 채울 때 범위를 어떻게 나누는가?
- [ ] 동의어 검사는 언제 도는가(저장할 때, 앱을 열 때)?
- [ ] LLM은 Claude API로 고정하는가, 로컬 모델 옵션을 두는가?
- [ ] 대상 앱의 실제 한도값은 얼마인가? (0단계 실험에서 측정)
- [ ] 외부 사이트에서 가져온 레퍼런스의 출처와 저작권 표시를 어떻게 하는가?
- [ ] 골든 샘플 블라인드 비교를 앱이 도와야 하는가, 수동으로 충분한가?

## 14. MVP 적합성 판단

1단계 범위는 **2단계 질문의 답이 없어도 만들 수 있다.** 메타데이터를 손으로 쓰고, 조립과 덜어내기가 LLM 없이 결정적으로 동작하기 때문이다. 남은 위험은 두 가지다. 하나는 Tauri 드래그가 세 앱에서 실제로 동작하는지(0단계에서만 확인 가능), 다른 하나는 `writing/naver-paragraph-style.txt`가 **현재 빈 파일**이라 글 스타일 레퍼런스가 비어 있다는 점이다. 따라서 v2는 MVP 구현에 적합하다고 판단하고 1단계로 진행한다.
